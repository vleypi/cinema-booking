## 3.2 Права ролей и доступ к чужому кинотеатру

Тест endpoint-access перебирает все эндпоинты персонала. Для каждого эндпоинта он выполняет четыре проверки:

- запрос без входа получает ответ 401;
- сотрудник с временным паролем получает ответ 403 с просьбой сменить пароль;
- каждая из пяти ролей получает доступ строго по таблице 6 технического задания;
- сотрудник с нужным правом не получает данные чужого кинотеатра.

Суперадминистратор при этом получает доступ к любому кинотеатру. Доступ к ресурсам проверяется по идентификатору кинотеатра в адресе и по идентификатору самого ресурса.

Тест проверен на внесенной ошибке. На эндпоинте схемы зала право администратора временно заменили правом менеджера. Тест упал на этом эндпоинте, после отката изменения снова прошел.

Тест входа отдельно проверяет подделанные access-токены. Сервер отвечает 401 на поврежденную подпись и на подпись чужим ключом. Так же он отвечает на токен без подписи и на токен с подмененным идентификатором сотрудника.

# 6 Замечания без дефектов

В ходе проверки отмечены особенности поведения, которые дефектами не являются:

- Новый кинотеатр создается скрытым с сайта. Зрители увидят его только после явной публикации.
- Отказ в правке сотрудника чужого кинотеатра приходит с сообщением «Недостаточно прав». Одно правило закрывает чужой кинотеатр, собственную учетную запись и старшую роль.
- Запрос с неверным телом к залу чужого кинотеатра получает ответ 400 раньше проверки доступа. Ответ не раскрывает данных чужого зала, с верным телом сервер отвечает 403.
- Safari не сохраняет cookie с флагом Secure на адресе http://localhost. Для локального запуска в Docker нужен Chrome или значение COOKIE_SECURE=false.
