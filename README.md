# cinema booking

Система продажи билетов и управления кинотеатрами. Подходит для одного кинотеатра и для целой сети: у каждого свои залы, цены, расписание и сотрудники.

## О приложении

Система состоит из сайта для зрителей, приложения персонала и серверного API. Конкретный кинотеатр подключается настройкой, в качестве примера используется кинотеатр «Луч».

Зритель смотрит афишу и расписание, выбирает места на схеме зала, оплачивает заказ картой и получает билеты с QR-кодом на почту. Регистрация не нужна: личный кабинет открывается по одноразовому коду из письма. В нём видны заказы, билеты можно вернуть до начала сеанса. На время оплаты места бронируются, поэтому одно место не продаётся дважды.

Сотрудники работают в приложении персонала, оно открывается на компьютере и на телефоне. Администратор сети добавляет кинотеатры и назначает администраторов, администратор кинотеатра ведёт сотрудников, залы и цены. Залы рисуются в редакторе схем: ряды, кресла, диваны на двоих, места для кресел-колясок и проходы. Места делятся на ценовые зоны, а цена зависит ещё от времени суток. Менеджер ведёт каталог фильмов с постерами и расписание сеансов без пересечений по залам. Кассир продаёт и возвращает билеты, контролёр сканирует QR-коды камерой телефона и сразу видит, почему билет не подходит, если проход закрыт.

Права сотрудников зависят от роли и действуют только в тех кинотеатрах, к которым они привязаны.

Серверная часть написана на NestJS с PostgreSQL и Redis, приложения на Next.js. Всё лежит в одном монорепозитории на pnpm и Turborepo.

Приложение находится в разработке. Часть функций для зрителей, кассы и контроля прохода ещё не готова.

## Как запустить

Потребуются Git и Docker. Для разработки без Docker ещё Node.js 24 или новее и pnpm.

В Docker:

```bash
git clone https://github.com/vleypi/cinema-booking.git
cd cinema-booking
cp docker/.env.example docker/.env
pnpm up
```

В `docker/.env` нужно задать `JWT_ACCESS_SECRET` (случайная строка не короче 32 символов) и `SEED_SUPER_ADMIN_PASSWORD`. Миграции применяются при старте сервера. Суперадминистратора с логином `admin` создаёт команда:

```bash
docker compose -f docker/docker-compose.yml exec backend node dist/database/seed.js
```

После запуска приложение персонала доступно по адресу http://localhost:3002, сайт для зрителей по адресу http://localhost:3001, API по адресу http://localhost:3000/api, документация API по адресу http://localhost:3000/api/docs.

Для разработки нужны запущенные PostgreSQL и Redis, настройки лежат в `backend/.env.example`:

```bash
pnpm install
cp backend/.env.example backend/.env
pnpm dev
```

Команда `pnpm check` прогоняет lint, тесты, сборку и проверку типов. Тесты API с базой запускаются командой `pnpm test:e2e`, для них поднимаются отдельные PostgreSQL и Redis командой `pnpm db:test`.

## Структура

```
cinema-booking/
├── backend/               API на NestJS
│   ├── src/modules/       auth, cinemas, films, halls, sessions, staff, time-bands, media
│   ├── src/common/        валидация, пагинация, безопасность, время
│   ├── src/database/      миграции и начальные данные
│   └── test/              e2e-тесты
├── frontend/
│   ├── crm/               приложение персонала
│   ├── cinema/            сайт для зрителей
│   └── shared/            клиент API, компоненты, настройки
├── docker/                Docker Compose и Dockerfile
├── docs/                  ТЗ, ER-диаграмма, план, отчёт о тестировании
├── .github/workflows/     CI
├── pnpm-workspace.yaml    пакеты монорепозитория
└── turbo.json             задачи Turborepo
```
